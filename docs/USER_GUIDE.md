# GradeAI User Guide

## Introduction

GradeAI is an academic workflow platform designed to help educators manage assessment, monitor student performance, identify academic risk early, and support students before problems become more serious.

The platform brings together:

- assignment creation
- rubric-based marking
- student submissions
- AI-assisted grading
- lecturer review and final decision-making
- academic integrity checks
- moderation workflows
- student feedback release
- guided student improvement support
- analytics and early intervention insight

GradeAI does not replace lecturer judgement. AI is used to support marking, explanation, and pattern detection, but lecturers remain responsible for reviewing work, approving grades, and deciding what is released to students.

## Who GradeAI Is For

GradeAI supports different types of users:

- **Lecturers / Teachers**
  - create assignments
  - define rubrics
  - review submissions
  - use AI-assisted marking
  - approve and release grades
  - monitor performance patterns
  - identify students who may need support

- **Students**
  - view published assignments
  - submit work
  - view released grades and feedback
  - use `Explain My Grade` to better understand performance and improve

- **Moderators**
  - review moderation cases
  - confirm, adjust, return, or escalate review outcomes

- **Admins**
  - monitor platform activity
  - oversee users, assignments, submissions, and system-level trends

## Getting Started

## 1. Sign In

Go to the GradeAI login page and sign in using your account.

After signing in, the system takes you to the correct workspace based on your role.

- Lecturers see the lecturer dashboard
- Students see student-facing pages
- Admins see the admin dashboard

If you are new to the system, start by opening the dashboard and checking the menu items available to your role.

# Lecturer Guide

## 2. Lecturer Dashboard Overview

The lecturer dashboard is the main starting point for teaching workflows.

It helps you:

- see assignment activity
- notice grading backlogs
- monitor student performance trends
- spot integrity or moderation cases
- identify where students may need support

You should think of the dashboard as a teaching and review workspace, not just a marking page.

## 3. Creating an Assignment

To create an assignment:

1. Open **Assignments**
2. Select **Create Assignment**
3. Enter the assignment details, such as:
   - title
   - module code
   - description
   - due date
   - maximum score
4. Add the marking rubric

The rubric is important because it defines how the work should be judged. It also gives the AI a structured marking guide.

A good rubric should make expectations clear, both for students and for lecturers reviewing the result later.

## 4. Example: Creating an Assignment in GradeAI

To make this more practical, here is an example using one of the sample assignments already used in the platform.

### Example assignment

**Title:** `Database Normalisation Case Study`  
**Module code:** `CS220`  
**Maximum score:** `80`  
**Target cohort:** `200`  
**Target department:** `Computer Science`

### Example assignment brief

A lecturer could create the assignment like this:

> Redesign the provided enrolment dataset to third normal form and explain the trade-offs in your final schema. Include entity assumptions, functional dependency analysis, and a short note on implementation compromises.

This is a strong example because it gives students a clear technical task, requires structured reasoning, and allows marking against well-defined criteria.

### How a lecturer would enter it

In the assignment form, the lecturer would fill in:

- **Title:** `Database Normalisation Case Study`
- **Module code:** `CS220`
- **Maximum score:** `80`
- **Description / brief:**
  > Redesign the provided enrolment dataset to third normal form and explain the trade-offs in your final schema. Include entity assumptions, functional dependency analysis, and a short note on implementation compromises.
- **Target cohort:** `200`
- **Target department:** `Computer Science`

At this stage, the lecturer can save it as a draft first before publishing.

## 5. Example Rubric

The lecturer would then define the marking guide using the rubric.

### Rubric criteria

#### 1. Dependency Analysis
- **Weight:** `20`
- **Description:**  
  Identifies functional dependencies clearly and justifies them against the case material.

#### 2. Schema Design
- **Weight:** `25`
- **Description:**  
  Produces a coherent normalised schema with appropriate keys and relations.

#### 3. Trade-off Discussion
- **Weight:** `20`
- **Description:**  
  Explains design compromises, implementation costs, and any denormalisation considerations.

#### 4. Technical Communication
- **Weight:** `15`
- **Description:**  
  Uses clear diagrams, notation, and concise explanation throughout.

### Why this example works well

This sample assignment shows how GradeAI is supposed to be used:

- the assignment brief is clear and realistic
- the rubric breaks the task into understandable marking criteria
- the lecturer still controls the academic expectations
- the AI can use the rubric as grading context
- students later receive feedback that connects back to the rubric

In other words, the lecturer is not just uploading an assignment. They are defining the academic expectations in a structured way, which helps both marking quality and student learning.

## 6. Publishing an Assignment

After creating and checking the assignment:

1. Save it as a draft if you are still working on it
2. Publish it when it is ready for students

Only published assignments are intended to be visible to students.

Assignments can also be targeted to the correct student groups where relevant.

## 7. Student Submission Flow

Once published, students can open the assignment and submit their work.

As a lecturer, you can then:

- open the assignment detail page
- view all submissions
- review submission status
- track which work has been graded, approved, released, or sent for moderation

This gives you a single place to manage the full marking workflow.

## 8. AI-Assisted Grading

For supported submission files, GradeAI can generate draft grading output.

This may include:

- draft score suggestions
- criterion-level comments
- draft feedback
- confidence or review signals

Important:
- AI grading is not the final grade
- it is a draft to help the lecturer review more efficiently

The lecturer remains responsible for checking the quality, fairness, and relevance of the grading outcome.

## 9. Lecturer Review and Final Decision

After AI grading:

1. Review the draft result
2. Edit marks if needed
3. Edit feedback if needed
4. Decide whether the work is ready for approval
5. Approve the grade when satisfied
6. Release the result when it is ready for the student to see

Approval and release are separate.

This matters because:

- a result may be reviewed internally first
- not everything approved is immediately ready for student release

Students should only see results after release.

## 10. Academic Integrity and Similarity Review

GradeAI includes in-house similarity checking.

This helps lecturers identify submissions that may be unusually similar across the cohort.

The system compares assignment submissions and highlights work that may need closer review.

This is not an automatic accusation of misconduct. It is a review aid.

Use it to:

- identify suspicious overlap
- compare flagged work more carefully
- decide whether the case needs further academic integrity review

The goal is to support fair review, not automate disciplinary decisions.

## 11. Moderation Workflow

Some submissions may require moderation.

In moderation, another reviewer may:

- agree with the original judgement
- adjust the result
- return it for further review
- escalate the case

This helps protect consistency and academic quality.

Moderation is especially useful where:

- the case is borderline
- there are integrity concerns
- the result requires another academic judgement
- institutional policy requires review

## 12. Releasing Feedback to Students

Once work has been reviewed and approved, the lecturer can release it.

After release, students can view:

- final score
- lecturer-approved feedback
- released assessment outcome

Students should not see draft AI output before release.

This keeps the process academically safe and lecturer-controlled.

## 13. Monitoring Student Risk and Performance

GradeAI is designed not only to manage assignments, but also to help educators act earlier.

The platform helps you notice:

- weak performance patterns
- repeated low rubric outcomes
- missing submissions
- integrity concerns
- recurring issues across a cohort

This can support earlier intervention before students disengage or fail repeatedly.

It can also help lecturers reflect on whether:

- the assignment is too easy
- the assignment is too difficult
- parts of the curriculum may need review
- many students are struggling with the same concept

The goal is to support both student success and academic quality.

# Student Guide

## 14. Viewing Assignments

Students can open **Assignments** to see available work.

They should be able to:

- read the assignment brief
- check the due date
- understand the expectations
- submit work before the deadline

Only assignments that are meant for the student should appear in their view.

## 15. Submitting Work

To submit work:

1. Open the assignment
2. Upload the required file
3. Confirm the submission completed successfully

After submission, the student should be able to refresh and still see that the submission is recorded.

## 16. Viewing Results

Students can view results only after they have been released.

When a result is released, students can access:

- the final score
- lecturer-approved feedback
- released grade information

If a result has not been released yet, it should not appear as a final visible grade.

## 17. Explain My Grade

One of the most useful student features is **Explain My Grade**.

This feature helps students understand:

- why they received the result they did
- where they were weak
- what they did well
- how they can improve next time

It is important to understand that this feature is not meant to simply give students answers.

Instead, it is designed to guide reflection and improvement.

The purpose is to help students learn better, not bypass learning.

# Moderator Guide

## 18. Reviewing Moderation Cases

Moderators can open the moderation workspace and review cases that require another academic judgement.

A moderator may:

- review the submission and existing feedback
- check the marking outcome
- decide whether to agree, adjust, return, or escalate

This supports fairness, consistency, and institutional quality standards.

# Admin Guide

## 19. Admin Oversight

Admins use GradeAI for oversight rather than marking.

Admin views help with:

- monitoring users
- reviewing assignment and submission activity
- checking moderation pressure
- reviewing system-level patterns

This gives institutions visibility without turning the admin dashboard into a teaching workspace.

Institution-level reporting also lives in the admin area. Pages such as `Institutional Insights`, `Accreditation`, and `External Examiner` are meant for oversight, quality review, and reporting, so they sit under `Admin -> Reports` rather than the lecturer sidebar.

## 20. Best Practices for Lecturers

To get the best from GradeAI:

- write clear assignment briefs
- build strong rubrics
- treat AI grading as draft support, not final truth
- review all important outcomes before release
- use analytics and risk signals to support students earlier
- use integrity flags as prompts for review, not automatic decisions

## 21. Best Practices for Students

Students should:

- read the assignment carefully
- submit before the deadline
- use feedback constructively
- use `Explain My Grade` to improve understanding
- treat the system as a learning support tool, not just a grade display

## 22. Final Note

GradeAI is designed to help educators and students work more effectively together.

For lecturers, it provides better visibility, stronger workflow support, and earlier warning signs where students may need help.

For students, it provides clearer feedback, guided reflection, and support for improvement.

The overall purpose of the platform is simple:

- help students improve earlier
- help educators act earlier
- support academic quality
- keep final academic judgement in human hands
